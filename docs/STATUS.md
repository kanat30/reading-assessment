**What's working / built:**
- **One norm set per session (2026-07-26, D1):** `resolveNorms()` (`lib/scoring/norms.ts`) resolves `{grade, period, basis, table_edition, passage_level, cuts}` **once at score time** — banding by the **student's grade** (new `assessments.student_grade`, migration 0023, picked 4–8 at creation) with a labeled passage-level-estimate fallback — stored in `scores_json.norms` and rendered by every surface (report header/band, group median, print view, AI-summary prompt). Summary text can no longer contradict the header (the old pipeline hardcoded "grade-6 spring" into every stored summary; a live dry-run found stored summaries still citing "benchmark of 150"). Below-grade passages state both facts: "Passage: Level 5 (below grade level) · Benchmarked against Grade 6 norms (MOY)". `scripts/backfill-norms.ts` (dry-run default, `--apply`) attaches norms + prosody dimensions to existing sessions and regenerates stale summaries — never over a teacher's override; demo-tenant hand-written summaries kept unless `--demo-summaries`.
- **One deterministic prosody pipeline (2026-07-26, D2):** Pace/Smoothness/Phrasing computed server-side at score time (`computeProsodyDimensions`, each rule documented; thresholds calibrated on the 30 real sessions via `scripts/recalibrate-prosody.ts` so values spread across 1–4 — the old client rule pinned pace at 4 for any WCPM≥90). **Expression is teacher-rated**: "Not yet rated" until set via the dot-click override flow; never auto-scored. Headline prosody = median of stored dimensions; total shows `/16` only once Expression is rated, else `/12 (Expression not yet rated)`. The Claude NAEP holistic level renders only inside the AI Observation block, labeled as an observation. Per-dimension overrides work end-to-end (migration 0024: `prosody_dimensions.*` path, value/dimension validation, unknown paths now error instead of silently recording); surfaces re-render from stored values with an "edited" marker. Replaces three divergent computations, including the print view's hardcoded Expression/Phrasing/Smoothness=3.
- **Real percentiles, one band rule (2026-07-26, D3):** `HASBROUCK_TINDAL_NORMS` extended to all five published cuts (p10/p25/p50/p75/p90), grades 4–8 × BOY/MOY/EOY — 75 values verified against two independent reproductions per grade. Both crude estimators deleted (legacy grade-6-spring interpolation; "+30% spread" heuristic). Percentile display = exact cut or range language ("between the 25th and 50th percentiles"), never an interpolated point. One band function (`getBand` in `lib/scoring/norms.ts`) and one vocabulary: At/Above · Below · Well Below Benchmark. `ScoringMetrics.percentile_estimate/percentile_band` remain as deprecated read-only fields in old scores_json.
- **Comprehension AI-failure is explicit, never silent zeros (2026-07-26):** grading failure stores `grading_status: "ungraded"` (+ per-answer `ungraded`; migration 0025 widens the status CHECK), score `null` — "Needs review" in the report, excluded from group aggregates, teacher prompted to re-grade or review manually. Previously an AI outage graded every answer "incorrect" at score 0.
- Teacher auth (Supabase email/password) and dashboard with assessment/session lists, current-week default window, date filters, shareable assessment links, templates, numbered students.
- Student flow (no login): `read/[token]` → name entry → recording (MediaRecorder) → comprehension → done. **The read is a fixed 60-second timed sample: the app auto-stops and advances at the limit (no reliance on the student tapping stop), shown as a calm depleting bar with no ticking numbers and an "Almost done" cue in the final 10s; a manual stop remains for early finishers.** Upload retries with backoff and has offline recovery (auto-uploads when the connection returns); a failed upload keeps the recording so the student never re-reads.
- Scoring pipeline (`POST /api/score`): Deepgram `nova-3` (`filler_words`, passage `keyterm` prompting) → deterministic alignment/error classification → WCPM, accuracy, Hasbrouck–Tindal benchmark bands (BOY/MOY/EOY, median-of-3) → prosody (1–4) → error patterns → Claude teacher summary. Hardened: 25MB/10min caps, per-token rate limiting.
- **Norms table verified against the published editions (2026-07-24):** every `HASBROUCK_TINDAL_NORMS` value checked against the sources; five grade 4–6 values corrected to the official 2017 table (worst: grade 6 EOY p50 was 162 instead of 146 — a 16-WCPM-inflated At-Benchmark bar for Level 6 end-of-year). Grades 7–8 confirmed to match the 2006 compilation (the 2017 update stops at grade 6) and now cited as such. Legacy grade-6-spring `NORMS` in `metrics.ts` and the AI-summary's hardcoded benchmark (150→146) aligned to 2017. Bands are computed at render time, so all reports pick up the corrected cutoffs with no backfill. See DECISIONS 2026-07-24.
- **Not-reached handling (2026-07-11):** since the read is a fixed 60s sample, words past where the student stopped are excluded from scoring, error patterns, error counts, and the transcript (which collapses the unread remainder behind a "reached N of M words" marker) — they are no longer shown or counted as omission errors. Cutoff derived by `getLastReachedIndex()` (`lib/scoring/metrics.ts`). Migration 0019 applies the same cutoff to the override metric-recompute (fixes a latent bug where the first word-override recomputed accuracy over the whole passage). See DECISIONS 2026-07-11.
- **Stop-point robustness (2026-07-14):** fixed a case where a student stopping on a word that recurs later in the passage (e.g. the first "construction") had their stop point teleported to the later copy, marking the whole intervening paragraph as read-but-omitted and corrupting WCPM/accuracy/band. Two deterministic fixes: (A) the NW aligner (`alignment.ts`) now biases ties toward the *earliest* occurrence of a repeated word, keeping the read contiguous; (B) `getLastReachedIndex()` now returns the end of the leading contiguous read — it cuts at the first large silent gap followed by only a sparse stray tail, while leaving genuine mid-passage skips counted as omissions. Guarded by `scripts/validate-stop-point.ts` (3 scenarios, all pass). Score-time only, no migration. See DECISIONS 2026-07-14.
- **Comprehension submit no longer blocks on AI (2026-07-14):** the student's "Submit answers" was waiting 10–30s per passage for the synchronous Claude grading call — output only the teacher sees. `POST /api/comprehension` now persists the raw answers, returns immediately, and grades in the background via `waitUntil`; the report shows "Grading…" for the brief pending window. Student submit is now a fast DB write. No migration. See DECISIONS 2026-07-14.
